## Why

hello-chelis is pinned to Chelis `0.14.0` and carries four hand-maintained GitHub
Actions workflows (`ci`, `lint`, `nightly`, `release`) that duplicate toolchain
download, Docker build, pin-guard, and nightly-issue logic already reviewed and
centralized in the private `Chelis-Lang/ci` repository. Moving to Chelis `0.17.1`
keeps the corpus current with the released compiler, and delegating CI to the
shared `consumer.yml` reusable workflow removes copy-pasted mechanics, gives us
digest-authenticated toolchain installs, and lets future compiler bumps happen by
editing pins instead of workflow bodies.

## What Changes

- Bump the Chelis compiler pin from `0.14.0` to `0.17.1` in `reef.toml`, `reef.lock`,
  the Docker build args, and `docker/docker-compose.yml`.
- Regenerate all compiler-produced sidecars against `0.17.1`: Deep s-expression
  `.dp` files (`scripts/regen_deep.py`) and any Octant `spans.json` output, and
  re-verify the C-backend golden outputs under `verify/`.
- Resolve any source-level breakage introduced by the `0.14 → 0.17` compiler jump
  so `chelis check`, `chelis lint --check`, and `chelis test tests/` pass clean.
  **BREAKING** if 0.17.1 changes surface syntax/semantics used by the corpus.
- Replace the four local workflow bodies with thin caller wrappers that invoke
  `Chelis-Lang/ci/.github/workflows/consumer.yml` at a reviewed full commit SHA,
  selecting the `hello-chelis-ci`, `hello-chelis-lint`, `hello-chelis-nightly`, and
  `hello-chelis-release` profiles. Each wrapper keeps only its own event triggers,
  concurrency, and permission ceiling.
- Add `.github/chelis-toolchains.json` (`chelis-toolchain-digests/v1`) with the
  independently reviewed `0.17.1` linux-x86_64 and darwin-arm64 archive digests,
  and pass the matching `chelis-linux-sha256` from each toolchain-installing
  wrapper so the central pin-consistency guard validates against the committed lock.
- Retain `.github/valgrind-known.supp` (still consumed by the central nightly job)
  and keep `scripts/regen_deep.py`, `tests/`, and `verify/` as the consumer-owned
  gates the central profiles invoke.

## Capabilities

### New Capabilities

- `chelis-toolchain-pin`: the single exact Chelis compiler version the repository
  targets, kept consistent across the Reef manifest/lock, the Docker image, and the
  `.github/chelis-toolchains.json` digest lock, with all compiler-generated sidecars
  regenerated byte-for-byte against that version.
- `shared-ci-workflows`: hello-chelis CI, lint, nightly, and release delegated to
  the central `Chelis-Lang/ci` `consumer.yml` reusable workflow through immutable,
  SHA-pinned caller wrappers that own only triggers, concurrency, permissions, and
  the manifest-derived pins passed to the selected profile.

## Impact

- **Toolchain / manifest**: `reef.toml`, `reef.lock`, `docker/Dockerfile`,
  `docker/docker-compose.yml`.
- **Generated artifacts**: Deep `.dp` sidecars, Octant `spans.json`, `verify/expected/*`
  golden outputs — regenerated and re-committed.
- **CI**: `.github/workflows/{ci,lint,nightly,release}.yml` rewritten as wrappers;
  new `.github/chelis-toolchains.json`; branch-protection required-check context
  names change when local jobs become reusable caller jobs.
- **External dependency**: adds a build-time dependency on `Chelis-Lang/ci` being
  resolvable from this repo (private-action access) and on `CHELIS_RELEASE_TOKEN`
  reaching the reusable workflow.
- **Non-goals**: no change to Reef dependency pins (`coral`, `nautilus`, `school`,
  `octant`, `c-earchin`) beyond what a `0.17.1` rebuild requires; no product source
  behavior change beyond compiler-compatibility fixes.
