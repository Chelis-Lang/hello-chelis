## Context

`hello-chelis` is a release-artifact consumer: CI and learners build an Ubuntu image that downloads the Chelis toolchain tarball and installs pinned Reef packages. The repository currently pins Chelis `=0.14.0`; its lockfile also records Coral `0.7.30` and Nautilus `0.7.33`. Coral `0.7.31` and Nautilus `0.7.34` are the published `0.16.1`-compatible releases, and `../nautilus` provides the reference conformance/CI layout.

A read-only audit with the direct `0.16.1` binary reports eight MUST failures: missing `AGENTS.md`, `docs/CHELIS_SURFACE.md`, `docs/UPSTREAM_BUGS.md`, `tests_neg/`, pin-bump/scaffolding guidance, shared skills, and CI pin/conformance enforcement. The existing `tests/negative/`, `docs/discrepancies.md`, README, curriculum, generated Deep sidecars, Docker flow, and Python/C-backend harnesses contain repository-specific teaching intent that scaffolding must preserve.

## Goals / Non-Goals

**Goals:**

- Make `=0.16.1` the single compiler contract across Reef, Docker, workflows, generated conformance artifacts, and learner documentation.
- Adopt all MUST-tier shell-contract artifacts and blocking CI enforcement without forking toolchain-owned content.
- Re-probe the corpus as a de-narrowing event, removing obsolete compatibility work while preserving explicit negative and blocked evidence.
- Prove a fresh authenticated image still supports the complete runnable curriculum and verification surface.

**Non-Goals:**

- Support `0.16.0` as an intermediate or retain compatibility with `0.14.0`.
- Add new lessons, examples, or public learner APIs unrelated to `0.16.1` compatibility.
- Build Chelis from source, link Chelis crates by path, or replace release-tarball image consumption.
- Copy or locally fork shared skill content generated by the pinned toolchain.

## Decisions

### 1. Audit, scaffold, then mechanize the direct bump

Use the deterministic `~/.chelis/toolchains/0.16.1/bin/chelis` binary while the repository still routes bare `chelis` to `0.14.0`. Preserve the initial audit JSON as the worklist. Because complete required artifacts are absent, run `reef conform init hello-chelis --module-prefix Hello --output .`, review the retrofit diff for overwritten learner intent, and then use `reef conform bump 0.16.1` to rewrite pins, restamp managed content, and re-materialize skills. Run `conform sync` only after the Reef pin is `=0.16.1`, as an idempotence/ownership check.

This follows the toolchain workflow instead of hand-authoring managed blocks. Running only `conform bump` was rejected because the audit proves that initialization-level artifacts are absent; running `sync` before the pin change was rejected because it restamps to the current `=0.14.0` Reef pin; hand-editing every artifact was rejected because it would create downstream-owned forks.

### 2. Treat all pin consumers as one transaction

Advance `reef.toml`, regenerate `reef.lock`, update the Docker build default and Compose image tag, and update every workflow audit mirror/build argument together. Resolve the dependency closure against `0.16.1`, explicitly consuming Coral `0.7.31` and Nautilus `0.7.34` and selecting compatible published releases for the remaining shells. The image must report `chelis 0.16.1` before tests run.

Editing only `reef.toml` was rejected because CI and Docker can silently execute another binary. An offline consistency guard must discover all toolchain-installing workflows rather than maintain an incomplete filename allowlist.

### 3. Preserve ownership boundaries in conformance material

Generated managed blocks and the shared `agent-skills/` set come from the `0.16.1` toolchain and retain their upstream stamp. Existing repository prose remains outside managed fences. Any genuinely repository-local skill is declared in `[conform].local_skills`; a shared-skill customization, if required, uses only the supported trailing `shell-local` block.

Copying the Nautilus skill bodies was rejected: Nautilus is a structural reference, while Chelis `0.16.1` is the content authority.

### 4. Re-probe before carrying compatibility claims

Inventory version-sensitive claims and workaround citations in source, `docs/discrepancies.md`, shell docs, README, and curriculum. For each candidate, run the relevant `check`, `eval`/`test`, Reef build, and C-backend verbs inside the new image. A fixed limitation is de-narrowed and archived; a surviving limitation receives an executable `tests_blocked/` probe, expected sidecar, source citation, and `docs/UPSTREAM_BUGS.md` entry. Existing must-reject teaching examples are represented in the toolchain-native `tests_neg/` contract without losing their learner-facing role under `tests/negative/`.

Changelog-only disposition was rejected because a fix can differ by frontend, evaluator, package build, or C backend. Generated `.dp` and Octant artifacts are regenerated only from their source surfaces after compatibility edits; they are evidence of drift control, not substitutes for executable acceptance.

### 5. Put conformance ahead of the expensive image gate

Add a blocking CI guard that checks out full history, installs the exact Reef-pinned private toolchain through a pin-resolving authenticated installer, runs the offline workflow-pin guard, `chelis reef conform audit --explain`, and `chelis reef conform bump-check --base origin/main`. Image and corpus jobs depend on this guard. Release and nightly workflows expose the same `0.16.1` audit mirrors and derive runtime selection from the exact Reef pin where practical.

A shallow checkout was rejected because `origin/main` cannot reliably be compared. Continuing after a red conformance guard was rejected because an expensive green image job must not mask pin drift.

### 6. Keep the release-tarball image as the acceptance boundary

The authoritative repository acceptance oracle remains the blocking `.github/workflows/ci.yml` image path: build from a fresh checkout with authenticated release access, verify the compiler version, and run formatting/linting, Reef build/check, native tests, `--expect neg`, `--expect blocked` when populated, Deep drift, C-backend goldens, Octant round trips, c-earchin proofs, and fallback Python tests. Local commands mirror that path through `docker compose`; a host-only `reef setup` is insufficient evidence.

## Risks / Trade-offs

- **Scaffolding overwrites learner-specific prose** → Review the `conform init` diff before synchronization and keep local intent outside managed fences.
- **A dependency release is unavailable or not `0.16.1` compatible** → Stop the bump, retain the last known-good pin, and file a blocker with an executable probe instead of weakening exact pins.
- **A former workaround now passes only on one verb** → Record per-verb outcomes and narrow only the verified portion.
- **Duplicated negative fixtures drift** → Define one authoritative source or an explicit synchronization check while retaining both conform and learner-facing discovery contracts.
- **Docker validation is slow or private-token dependent** → Run cheap offline/conformance checks first and require the authenticated image gate before acceptance.
- **Generated diffs obscure semantic edits** → Separate source compatibility changes from regeneration review and never hand-edit generated artifacts.

## Migration Plan

1. Capture the `0.16.1` audit, initialize missing conformance artifacts with the explicit in-place retrofit command, and review ownership boundaries.
2. Perform the direct mechanized bump to `0.16.1`, run post-bump synchronization, and refresh the compatible dependency lock, Docker configuration, and workflow mirrors.
3. Re-probe and de-narrow the corpus, add negative/blocked evidence, then refresh managed and learner documentation.
4. Wire the blocking conformance guard and run the fresh-image acceptance oracle plus strict OpenSpec validation.
5. Land through a pull request only after every MUST row and acceptance lane is green.

Before merge, rollback is removal of the issue branch/worktree. If `0.16.1` fails a required validation, do not merge the pin: retain `=0.14.0` (or the newest independently proven good release), file the upstream blocker, and preserve a `tests_blocked/` reproducer. After merge, any rollback is a reviewed corrective pin-bump PR with the same audit and acceptance evidence, never a direct edit to `main`.

## Open Questions

- Which current discrepancy/workaround entries are fully fixed, partially fixed, or drifted on `0.16.1`? Implementation resolves this only through per-verb probes.
- Which published versions of `school`, Octant, and c-earchin form the final compatible closure alongside Coral `0.7.31` and Nautilus `0.7.34`? Lockfile resolution and the image gate determine the accepted set.
