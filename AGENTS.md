## Toolchain Policy

Install the pinned toolchain via `chelisup`; never hand-symlink a machine-global
default. Python is uv-managed. See the managed block above for the upstream contract.

## Pin Bump Checklist

A pin bump is a de-narrowing event. Bump only through a `chelis reef conform bump`
PR that runs the blocked-probe suite, the staleness/narrowing audit, and restamps
`docs/CHELIS_SURFACE.md`. Never edit the pin directly on `main`.

## Scaffolding Drift Rule

All shells share one scaffolding shape. Mirror any structural change into the
sibling shells in the same change set, or record a per-repo divergence. Contract
changes land upstream first (`Chelis-Lang/chelis`) and propagate here via
`chelis reef conform sync`.

## Repository Acceptance Oracle

`.github/workflows/ci.yml` is authoritative. Its conformance stage must pass
before the fresh release-tarball image runs native tests, negative/blocked
contracts, Deep and Octant drift checks, C-backend goldens, c-earchin proofs,
and the fallback Python harness. Do not claim completion from host-only checks.

## Ownership Boundaries

- Managed fenced blocks and `agent-skills/` are toolchain-owned; re-sync instead
  of editing them.
- Prose outside managed fences, learner examples, tests, and capability rows are
  repository-owned.
- `tests/negative/` is authoritative learner source; materialize `tests_neg/`
  through `scripts/sync_negative_tests.py`.
- Generate `.dp` and Octant artifacts only through their scripts; never hand-edit
  generated output.
